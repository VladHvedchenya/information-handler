# Information Handler

Учебное консольное приложение на Java 21 и Gradle. Читает UTF-8-файл,
строит дерево Composite и выполняет три операции над текстом.

## Запуск

Из корня проекта:

```bash
./gradlew run
./gradlew run --args="data/adventure.txt a"
./gradlew test build
```

Первый аргумент — путь к файлу, второй — одна буква для сортировки предложений.
По умолчанию используются `data/adventure.txt` и `a`. Относительный путь
отсчитывается от рабочего каталога процесса. Для путей с пробелами нужны
кавычки внутри `--args`, например `--args='"/path/my text.txt" a'`.
В IntelliJ IDEA выберите JDK 21 для проекта и запуска.

Программа выводит восстановленный текст, число букв и символов и результаты:

1. Максимальное количество предложений с одним общим словом, все слова,
   достигшие максимума, и соответствующие предложения. Повтор слова внутри
   одного предложения учитывается один раз. Регистр игнорируется, окончания
   не нормализуются, служебные слова не исключаются. При отсутствии слов
   максимум равен нулю; если слова встречаются лишь в одном предложении — единице.
2. Предложения по возрастанию количества заданной буквы без учёта регистра
   (`Character.toLowerCase`). При равенстве сохраняется исходный порядок.
3. Текст с переставленными первой и последней лексемами каждого предложения.
   Перестановка создаёт копию дерева, сохраняет разделители и длину предложений.
   Пунктуация перемещается вместе с лексемой: `We love Java.` → `Java. love We`.

Коды завершения: `0` — успех, `1` — ошибка чтения, `2` — неверные аргументы.
Ошибка чтения логируется с исходной причиной через Log4j2.

## Модель и правила разбора

`TextComponent` — общий интерфейс. `TextComposite` представляет уровни
`TEXT`, `PARAGRAPH`, `SENTENCE`, `LEXEME`, а `TextSymbol` хранит одну кодовую
точку Unicode. Сущности хранят структуру, сервисы выполняют операции.

`TextSymbol` сравнивается по кодовой точке, а `TextComposite` — по типу и
упорядоченному списку детей. `hashCode` использует те же данные, `toString`
показывает структуру для диагностики; восстановлением текста занимается renderer.
У records методы `equals`, `hashCode`, `toString` создаёт компилятор.
Составные узлы изменяемы: после изменения детей меняется и их хеш. Поэтому
дерево, а также records со ссылками на него, нельзя изменять, пока они служат
ключами `HashMap` или элементами `HashSet`. Отдельные вхождения одинаковых
предложений хранятся в списках и не объединяются. При проверке циклов узлы
сравниваются по ссылкам, а не по содержимому.

Цепочка `DocumentParser → ParagraphParser → SentenceParser → LexemeParser`
создаётся один раз. Каждый обработчик выделяет фрагменты регулярным выражением
и передаёт их следующему обработчику. Шаблоны объявлены константами.

- Абзацы разделяются пустыми строками; поддерживаются LF, CRLF и пробелы или
  табуляция на пустой строке. Одиночный перенос остаётся внутри абзаца.
- Предложение завершается `.`, `!`, `?` перед пробельным символом или концом
  входа. Последний фрагмент без завершающего знака также сохраняется.
  Это упрощённый разбор: сокращения вроде `Mr. Brown` и сложная прямая речь
  не распознаются как специальные случаи.
- Лексема — непрерывная последовательность непробельных символов.
- Слова извлекаются отдельно: буквы Unicode с возможными внутренними
  дефисами и апострофами. Регистр нормализуется через `Locale.ROOT`.
- Пробелы, табуляция и переносы сохраняются. `TextRenderer` восстанавливает
  текст обходом дерева, не добавляя собственных разделителей.
- Общее число символов считается в кодовых точках, включая пробелы и переносы.
  Буквы определяются через `Character.isLetter`. Это не подсчёт визуальных графем.

## Ограничение памяти

Приложение предназначено для небольших учебных файлов: `Files.readString`
читает весь файл, а дерево сохраняет отдельные объекты для его символов.
Размер файла сам по себе не равен расходу памяти. Гигабайтные файлы требуют
другой организации хранения и обработки, а не только потокового reader.
